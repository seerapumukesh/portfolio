A lakehouse built for consistent analytics

Mukesh Seerapu

The data estate this replaced was a familiar shape: duplicated, point-to-point ETL jobs, each built to serve one downstream need, with no shared layer underneath them. Adding a new source usually meant a new notebook and a new pipeline, copy-pasted from whichever one was closest. That approach scales until it very suddenly doesn't.

What I built

I designed a medallion lakehouse — Bronze, Silver, Gold — on Azure Data Lake Storage Gen2 and Delta Lake. Azure Data Factory handled batch orchestration, Databricks (PySpark and Spark SQL) handled transformation at scale, and selected real-time events streamed directly into Delta tables through Structured Streaming, so batch and streaming data lived on the same platform instead of two separate ones. A metadata-driven ingestion framework meant a new source was configuration, not a new notebook written from scratch.

Trusted data, not just moved data

The Silver layer is where raw data became something usable — CDC, SCD Type 2 history, and data-quality rules applied there turned fragmented Bronze data into conformed datasets that BI and data science could both build on without redoing the same cleanup work twice. Every run was designed to be idempotent and replayable: immutable raw data, run IDs, Delta MERGE instead of blind inserts, and reconciliation gating before a watermark advanced — a rerun after a failure couldn't silently duplicate or lose anything.

The result

A single platform for batch and streaming data, reusable ingestion that didn't require new code for every new source, and pipeline runs that were safe to retry — replacing a growing pile of one-off ETL jobs with a foundation that could actually keep scaling.
