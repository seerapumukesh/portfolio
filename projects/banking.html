One trusted view of banking data

Mukesh Seerapu

Core banking, lending, and member data lived in disconnected systems — plus vendor files and REST APIs on top of that. Every team building a report was starting from a slightly different version of the same numbers, because there was no single place those numbers were reconciled against each other. The goal wasn't just "move the data somewhere central" — it was to make that central place something people could actually trust.

What I built

I designed a metadata-driven ingestion framework so that onboarding a new source meant adding configuration, not writing a new pipeline from scratch. Azure Data Factory and Talend handled orchestration, raw data landed in Azure Blob Storage as an immutable, replayable layer, and Snowflake became the analytical warehouse. On top of that, dbt organized every transformation into staging, intermediate, and mart layers, with automated tests and lineage so a broken assumption showed up as a failed test, not a wrong number three reports downstream.

Making it safe to fail

The part that mattered most in practice wasn't the happy path — it was what happened when something went wrong mid-run. Every pipeline used watermarks and run IDs so a failed job could restart without losing or duplicating data, and reconciliation checks had to pass before a watermark was allowed to advance. That combination meant a 2am failure was a routine rerun, not an incident that needed someone to manually figure out what state the data was left in.

The result

A centralized, governed warehouse with reusable source onboarding, tested transformations, and traceable data flowing into downstream reporting — 8+ source systems unified into one platform that teams across the business could build on with a consistent set of definitions.
